# Task and Continuation Data

The installed runtime's canonical workflow policy governs task states and
allowed actions. Use the policy/action metadata returned by the bound harness;
an explanatory copy in a resource snapshot does not override runtime authority.
Do not derive a policy path from this reference's physical location.

Resource procedures come from the selected project snapshot. State-policy
compatibility and resource freshness are distinct checks, not permission
to substitute installation instructions silently.
Mutations need expected revisions; ACT invalidates prior acceptance evidence.
Plans use stable keys and UUID task records. Artifacts and sessions preserve
registered evidence/progress, not authenticated execution or native-tool control.
