# Methodology

ODD means Organic Driven Development. Inspect existing behavior, establish
authority, resolve uncertainty and select proportionate work. Questions and
proposal-only requests remain read-only.

Honor the selected project mode. Light work keeps one bounded task record,
authorized scope and real verification/review evidence; it does not require
the formal specification/design/approval chain. Sensitive or substantial work
uses SDD, current content-bound approvals and scenario traceability.
Unknown risk is not low risk. A small diff does not justify weaker treatment
of security, data, shared contracts, concurrency or external effects.

Preserve the original request. Do not invent decisions, metrics, approvals,
research, tools, test results or authenticated identity. Ask about consequential
ambiguities and disclose every missing check or unavailable runtime capability.
Classification and outcome evidence are attributed attestations, not a proof
of semantic truth. Existing host/repository rules and actual runtime gates
prevail; methodology text is not a sandbox or universal tool interceptor.
