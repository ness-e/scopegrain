# Plan Work

Inspect existing plans, specifications and implementation first. Identify
the actual gap. Do not produce another plan for completed work or impose a
formal graph on a genuinely light task. An explicitly requested formal plan
uses the SDD path even when a lighter route would have been possible.

Read the settled structured specification, approved design and evidence PLAN.
Final outcome evidence cannot be required before the work exists.
Preserve the original request, constraints and exact behavioral examples.

Produce stable task keys, bounded scopes, scenarioRefs, dependencies, required
capabilities and exact proposed checks discovered in this project.
Cover all specification scenarios across the plan, not in every individual
task. Keep parallel writes independent and disjoint; mark unknowns blocked.
Do not select paid models, budgets or external effects without approval.

Present the complete plan and operational destinations for confirmation.
Persist only through available approved harness operations. Creation leaves
tasks in PLAN; it does not execute them. Return identity and the next gate.
