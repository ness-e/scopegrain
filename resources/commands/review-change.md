# Review a Change

Read the approved contract, complete diff, callers and actual check evidence.
Prioritize bugs, security, compatibility and missing regression cases.
With architecture focus, inspect boundaries and dependency direction;
do not substitute stylistic scores for demonstrated risks.

Return severity-ordered findings with file locations, evidence, impact and
concrete acceptance for correction. Separate confirmed defects from hypotheses.
If none are found, state that and record residual gaps.

Do not edit the change or approve work you authored as independent review.
The lead may persist the returned report through approved harness operations.
A waiver must be an explicit owner decision, not an invented reviewer.
