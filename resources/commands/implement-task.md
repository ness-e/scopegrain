# Implement One Task

Read the real task, original request, revision, scope and current code.
Resolve its Organic classification or formal SDD bindings with the available
project-bound runtime. Confirm authority, acceptance, dependencies and actual
authorized checks. Unknown task, unresolved product decision, missing consent
or a blocked methodology gate prevents implementation.

For light work use its bounded record and recorded authorization; do not
fabricate extra specification/design approvals. For SDD read the approved
specification, design, plan or single-task contract and assigned scenarios.
If the required capability is unavailable, report the gap instead of claiming
that a prompt or distinct context label enforced the gate.

Reproduce the defect with a causal failing test before changing behavior when
a runnable deterministic check exists. Explain exceptions. Apply the smallest
upstream fix, preserve unrelated work and run only authorized checks.
After repeated failure follow research-escalation; do not retry blindly.

Inspect the complete diff and raw evidence. Obtain independent review or an
explicit scoped owner waiver. Record actual verification and continuation in
the configured harness paths. For SDD, close only assigned scenario coverage;
one task does not certify the entire feature. Stop after this task: neither
publication, destructive effects nor the next task is implicitly authorized.
