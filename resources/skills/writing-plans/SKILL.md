# Implementation Plan

State verified existing behavior, missing behavior and the approved design.
Do not create another plan for implemented work or a formal document chain
for a light task that only needs its bounded record.

For each formal task specify inputs, actual files, exact interface, assigned
scenarios, acceptance checks, dependencies, write scope and authority.
State commands and working directories as proposed until actually authorized
and executed. Name unresolved decisions as blockers, not guessed parameters.

Keep coherent behavior with its tests and docs; file or line counts alone do
not decide task risk or force artificial splits.
Store the plan in configured harness paths and dry-run before apply.
Do not delegate an unsettled choice or claim that persistence is approval.
