# Specification

Inspect instructions, affected code, tests and existing decisions before
asking questions. State the observed gap, intended users and behavior,
scope, non-goals, compatibility constraints and unresolved assumptions.

Define acceptance cases and exact proposed verification commands/cwds.
Describe failure modes, security boundaries, data migration and recovery
where applicable. Do not select an external dependency using an unverified
claim; request permission for research if it requires network access.

Ask about consequential unknowns with a recommendation and tradeoffs.
Record the resulting spec as an artifact in the harness workspace.
Specification approval is not permission to deploy, install or overwrite
existing user configuration.
