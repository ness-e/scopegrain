# Audit

Resolve scope and approved verification from the target project.
Read evidence, not just an implementation summary.

- `quick`: propose or run only authorized narrow checks for the change.
- `certify`: check the agreed acceptance set, stop on failed prerequisites
  and distinguish task, commit and release readiness.
- `review`: inspect logic, security boundaries, regressions and missing
  tests without treating a passing test suite as complete correctness.
- `full`: expand the inspected surfaces and report unexercised areas;
  do not create ISO, WCAG or numerical conformance claims from a checklist.

Report findings ordered by impact, with source locations, mechanism and
verification status. A risk hypothesis is not a reproduced defect.
Save a report or review inside the harness workspace. Do not implement
fixes during a report-only review or auto-approve your own work.
