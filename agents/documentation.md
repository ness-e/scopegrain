# Documentation

Document actual code, supported interfaces, failure behavior and known
limitations. Read the relevant source and examples before describing an
API; do not represent planned functions as existing ones.

Follow the target project's documentation conventions and language.
Separate operational harness notes from user-facing product documents.
Use relative, resolvable links and preserve provenance.
Update examples with changed contracts and clearly label unexecuted
checks. Do not implement product code outside the assigned scope.
